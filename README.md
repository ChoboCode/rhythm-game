# SEVEN LANE — 6키 / 7키 리듬게임

등록된 곡의 **미리 저장한 채보**로 연주하는 6키 / 7키 리듬게임입니다.
현재 선택 화면에서는 `songs.json`에 등록한 곡과 미리 저장한 채보를 사용합니다.
위에서 내려오는 노트를 6키에서는 `S D F J K L`, 7키에서는
`S D F Space J K L`로 칩니다.

O2Jam 의 원곡과 `.ojn/.ojm` 채보는 저작권이 있어 쓰지 않았습니다.
대신 **직접 만들었거나 권리가 있는 음원**(Suno 로 만든 곡 등)을 사용합니다.

HTML·CSS·JS 코드는 `index.html` 한 파일에 있습니다. 전체 게임을 배포할 때는
`songs/`의 음원·채보·표지와 `assets/`의 이미지·결과 음악도 함께 올려야 합니다.
브라우저에서 곡 목록을 불러오도록 정적 웹 서버로 제공하세요.
처음 열면 `Bass Control`이 첫 디스크로 선택됩니다.
넓은 곡 선택 화면의 좌우 스펙트럼은 미리듣기의 왼쪽·오른쪽 주파수에 반응하며,
막대 기준선과 반사는 난이도 버튼 위치에 맞춰집니다.
현재 채보 제작·간주 선율 보강·검증 절차는 [인수인계서](인수인계서.md)에 정리했습니다.

## 바로 해 보기

`rhythm-game/` 폴더에서 `python -m http.server 8765`를 실행한 뒤
브라우저에서 `http://localhost:8765/`를 엽니다.

가사 황금빛 싱크를 확인하려면 같은 서버에서 [`lyrics-check.html`](lyrics-check.html)을 엽니다.
게임의 **가사 자막 만들기 → 한 줄씩 황금빛 점검**에서도 선택한 곡으로 열 수 있습니다.
0.5배부터 느리게 재생하며 **어절 또는 음절**을 고르고, 들리는 시작마다 Space나 큰 버튼을 순서대로 누릅니다. 마지막 탭은 줄 끝입니다.
찍은 시각을 적용하기 전에 원래 황금빛과 새 황금빛을 같은 음악 시각으로 비교할 수 있고, 적용 뒤에도 전후 비교와 되돌리기가 가능합니다.
한 줄 반복 재생, 원곡/보컬·악기 강조 듣기, 숫자로 세밀 조정, 어긋남 표시와 메모도 지원합니다.
수정 내용은 브라우저에 임시 저장되며, **보고서 복사** 또는 **점검 기록/수정 가사 JSON 받기**로 전달할 수 있습니다.
내려받은 가사는 게임 파일에 자동 적용되지 않습니다.

1. 목록에서 등록된 곡을 고르고 난이도와 키 모드를 선택한 뒤 시작합니다.
2. 소리와 노트가 어긋나면 **[싱크 보정]** 을 먼저 하세요. 보정은 두 가지입니다.
   - **입력 보정**: 딱 소리에 맞춰 8번 두드리면 자동으로 맞춰집니다(판정 기준).
   - **화면 보정**: 소리는 맞는데 노트만 먼저/늦게 지나가 보일 때 ±5ms 씩 조절합니다(그리기 전용).

## 조작

| 키 | 기능 |
|---|---|
| `S` `D` `F` `Space` `J` `K` `L` | 왼쪽부터 7개 레인 |
| 가운데 레인 자동 | `Space` 를 게임이 대신 칩니다 (설정에서 켬/끔) |
| `Esc` 또는 `P` | 일시정지 |
| `↑` `↓` | 연주 중 노트 속도 조절 |
| 화면 아래 7칸 | 휴대전화 터치 조작 |

NORMAL/HARD에서는 음원에서 측정한 드럼 강약으로 하이라이트를 찾고, 그 안의 강한 드럼 타격에 맞춰
노트가 급하게 느려졌다가 빠르게 내려옵니다. 빠른 3연타가 채보에 있으면 세 타격마다 속도가 다시 꺾입니다.
노트의 판정 시각과 음악 재생 속도는 그대로입니다.

### 가운데 레인 자동

엄지로 `Space` 를 치기 어렵거나 양손 여섯 개만으로 즐기고 싶을 때 켭니다.
BMS 의 오토 스크래치와 같은 개념입니다.

- 가운데 레인 노트를 게임이 **정확한 때에** 대신 칩니다(긴 노트도 끝까지 잡아 줍니다).
- 그 레인은 바탕색이 달라지고 판정대에 `AUTO` 가 붙어, 내가 칠 자리가 아님을 바로 알 수 있습니다.
- 켠 상태에서 `Space` 를 눌러도 판정에 영향을 주지 않습니다.
- 난이도가 달라지는 것과 같으므로 **최고 기록은 자동을 켰을 때와 껐을 때를 따로** 남깁니다.

긴 노트는 누른 채로 끝까지 유지해야 합니다. **머리와 꼬리를 각각 판정**하므로
일찍 놓으면 꼬리가 `MISS` 이고, 끝 근처에서 놓으면 놓은 정확도로 판정합니다.
누르고 있는 동안에는 약 16분음표마다 콤보가 1씩 오릅니다. 이 유지 틱은 정확도와
게이지 판정 수에는 포함하지 않고, 최대 콤보와 점수의 콤보 기준에는 포함합니다.
일시정지하거나 창을 벗어나면 그 자리에서 손을 뗀 것으로 처리합니다(저절로 성공하지 않습니다).
아예 놓쳤거나 중간에 끊긴 긴 노트는 판정이 끝났다고 그 자리에서 사라지지 않고,
**실패 표시(붉은기 도는 회색)로 바뀐 채 원래 속도로 끝까지 흘러내리다가 화면을 벗어나며 사라집니다**
— 실제 리듬게임처럼 몸통이 끊기지 않고 이어집니다.

판정은 `PERFECT`(±42ms) · `GREAT`(±85ms) · `GOOD`(±135ms) 이고, 그보다 벗어나면 `MISS` 입니다.
`PERFECT` 가 아니면 얼마나 빠르거나 늦었는지 **ms 로** 알려 줍니다.

노트를 맞히거나 빈 건반을 눌러도 입력과 동시에 짧은 타악기 소리가 납니다.
등록곡의 킥·탐 저음은 곡의 실제 베이스 음을 2초 간격으로 분석한 값에 맞추고,
스네어·하이햇·크래시는 고정 음정 없이 만듭니다. 직접 연 파일에는 음정 없는
타격을 사용합니다. 타악기 정보가 있는 채보는 킥·스네어·하이햇·크래시를 구분하며,
등록곡에서는 저음·중음·고음 타격의 세기를 각각 2초 간격으로 측정해 타격음의
어택·길이·음량을 구간에 맞춰 바꿉니다. 이 변화는 건반 소리에만 적용하고 원곡의
음량에는 영향을 주지 않습니다.
게이지가 가득 차 FEVER가 되면 노트를 맞힐 때 콤보 뒤에서 폭죽이 터지고 숫자가 올라옵니다.
빈 건반은 6키에서 `S/L` 하이햇, `D/K` 스네어, `F/J` 킥을 냅니다.
빈 입력은 판정·점수에 영향을 주지 않습니다.
롱노트는 머리에서만 소리를 내며 꼬리에서는 추가 타격음을 내지 않습니다.
HARD의 일부 지속 리드 구간은 분리한 반주 신호의 시작과 지속 길이를 확인해
1.4~2.5초 롱노트를 보강했습니다. 악기 분리의 `other`에는 기타 외 악기도
포함될 수 있어 악기 종류를 자동 확정하지 않습니다.
선택 화면과 일시정지 화면에서 드럼음을 끌 수 있습니다.

## 곡을 여러 개 넣어 두기

새 곡을 추가할 때는 `songs/` 폴더와 `songs.json`을 갱신합니다.

1. `songs/` 에 음악 파일을 복사합니다. 파일명 끝에 `_분_초`를 붙입니다(예: `내 첫 곡_3_12.mp3`).
2. `songs/songs.json` 에 목록을 적습니다.

```json
[
  { "title": "내 첫 곡", "artist": "Suno", "file": "내 첫 곡_3_12.mp3", "duration": 192.5,
    "charts": { "easy": "내 첫 곡_3_12.easy.json", "normal": "내 첫 곡_3_12.normal.json", "hard": "내 첫 곡_3_12.hard.json" } },
  { "title": "두 번째 곡", "file": "두 번째 곡_2_45.mp3", "duration": 165.2,
    "charts": { "easy": "두 번째 곡_2_45.easy.json", "normal": "두 번째 곡_2_45.normal.json", "hard": "두 번째 곡_2_45.hard.json" } }
]
```

목록에 등록한 곡에는 세 난이도의 `"charts"` 가 모두 필요합니다. 파일이 없거나 손상되면
게임이 오류를 표시하며, 연주 중에 채보를 자동 생성하지 않습니다. 현재 등록곡 채보는
`make-stems.py` → `attack-chart.py` → `add-melody-notes.py` → `refine-interludes.py` → `prune-weak-interlude-notes.py` 순서로 미리 만들고,
`verify-interlude-charts.py`와 `test-*.cjs`로 점검합니다. 정확한 명령과 백업 절차는 인수인계서에 있습니다.
`오늘부터 우리`의 반복 후렴은 `fill-our-chorus.py`로 빠진 보컬 음과 182초대 가사 시각을 추가 보정했습니다.
`우리 마을 축제`는 `refine-village-festival.py`로 두 번의 `주인공` 끝 음절에 롱노트를 넣고 간주의 빈 박을 일부 보강했습니다.
`War` 중간의 현악기처럼 들리는 선율은 `refine-war-strings.py`로 음높이 진행과 지속음에 맞춰 보강했습니다.
`Stay with me`의 반복 보컬은 `refine-stay-vocals.py`로 음절별 노트와 가사 시각을 보정하고 쉬어가기를 제거했습니다.
`My Cocktail`은 `refine-my-cocktail-piano.py`로 피아노 계열 타건을 보강하고 쉬어가기를 제거했습니다.
`Break It Down`은 `refine-break-melody.py`로 보컬·악기 선율 노트를 보강하고 마지막 세 번의 몰아치기만 남겼습니다.
`Last Stage` 후렴의 압축되거나 앞선 가사 시각은 `refine-last-stage-lyrics.py`로 수정했습니다.
각 곡 도입은 `refine-song-intros.py`로 실제 악기 타격이 있으나 빠져 있던 노트를 소량 보강했습니다.
등록곡의 건반 소리 분석값은 `python tools/build-keysound-profiles.py --write` 와
`python tools/build-sound-flow.py --stems <htdemucs 출력의 htdemucs 폴더> --write` 로 갱신합니다.
후자는 Demucs로 각 곡의 `drums` 성분을 먼저 분리해야 합니다
(`ffmpeg`·`librosa`·`numpy`·`scipy`·`demucs` 필요).
등록곡은 드럼과 멜로디의 실제 시작점에 맞춰 저장 채보를 사용합니다. 간주에서는 악기 스템의
음높이 변화와 지속 시간을 더 추적해 빠른 선율과 롱노트를 보강합니다. 자동 신호 검사를 통과해도
음악적으로 자연스러운지는 직접 들어 보고 연주하며 확인해야 합니다.

> 이 목록은 **웹 서버로 열었을 때만** 읽힙니다.
> `index.html` 을 파일로 바로 열면 브라우저가 폴더 접근을 막습니다.
> 반드시 로컬 서버나 정적 웹 서버로 열어야 합니다.
> 서버로 열려면 이 폴더에서 `python -m http.server 8000` 후 `http://localhost:8000` 에 접속합니다.

## 남아 있는 브라우저 자동 분석 코드

아래 내용은 현재 등록곡 채보를 생성하는 절차가 아닙니다. 현행 저장 채보 도구는 인수인계서를 보세요.

`index.html` 안의 채보 생성 스크립트(원래 `chart.js`)가 하는 일입니다.

1. **모노 축소** — 좌우를 합치고 22,050Hz 로 낮춰 분석량을 줄입니다.
2. **구간별 주파수 분석** — 1024 표본씩(약 11.6ms 간격) 잘라 FFT 를 돌립니다.
3. **대역별 타격 지점 찾기** — 5개 주파수 대역에서 각각 "소리가 갑자기 커지는 순간"을 찾습니다.
   문턱값은 주변 평균을 따라가므로 조용한 구간에서도 작은 타격을 잡습니다.
4. **한 번의 타격으로 합치기** — 킥과 하이햇이 같이 울리는 자리는 사람에게 한 번의 타격입니다.
   대역마다 노트를 만들면 기계가 찍은 티가 나므로 가까운 온셋을 하나로 묶습니다.
5. **BPM · 첫 박 · 확신도** — 자기상관으로 후보 박 길이를 뽑고, 그 배수·약수(1/4 ~ 4배)까지
   펼쳐 놓은 뒤 **실제 온셋이 박 위에 얼마나 정확히 떨어지는가**로 고릅니다.
   허용 오차를 절대 시간으로 재고 '격자가 실제로 쓰이는 비율'을 함께 보기 때문에,
   80↔160 같은 반/두 배 오인이 줄어듭니다.
6. **격자 정렬** — 확신도가 높을 때만 16분음표로, 보통이면 8분음표로,
   낮으면 아예 붙이지 않습니다. 확신 없이 억지로 붙이면 박자가 오히려 어그러집니다.
7. **레인 배치(패턴)** — 주파수로 레인을 바로 정하지 않습니다. 앞선 노트 16개를 보면서
   **좌우교대 · 계단 · 역계단 · 한 손 훑기 · 트릴 · 짧은 연타 · 2동시**를 섞어 엮습니다.
   최근에 쓴 모양은 잘 고르지 않고, 같은 네 묶음이 되풀이되면 다른 자리로 비킵니다.
   같은 레인 연타는 어려움에서만, 그것도 3번까지입니다.
8. **긴 노트** — 소리가 이어지는 정도, 박 위에서 시작하는지, 다음 타격까지의 여유를
   함께 보고 고릅니다. 끝나기 전에 같은 레인에 다른 노트가 오지 않도록 0.14초를 남깁니다.
9. **난이도** — 약한 타격부터 덜어 내고, 동시치기 수와 초당 노트 수를 제한합니다.
10. **타격음** — 그 타격에서 가장 세게 울린 주파수 대역으로 킥·스네어·하이햇·크래시 중
    하나를 고릅니다. 저음이 세면 킥, 고음이 세면 크래시 하는 식이라 곡마다, 또 같은 곡
    안에서도 구간마다 실제로 울린 소리를 따라 타격음이 달라집니다.
11. **밀도 구간** — 곡에서 온셋이 자연히 가장 몰린 20초를 찾아 그 구간만 노트를
    1.3배가량 더 채웁니다. 원래도 소리가 많은 자리라 부자연스럽지 않으면서, 한 곡
    안에서 밀도가 오르내리는 맛을 더합니다.

같은 곡·같은 난이도는 **항상 같은 채보**가 나옵니다(씨앗 고정). 저장해 둔 채보와 어긋나지 않습니다.

| 난이도 | 최소 간격 | 쓰는 레인 | 동시치기 | 초당 노트 | 패턴 | 긴 노트 |
|---|---|---|---|---|---|---|
| EASY | 4분음표 | 가운데 5개 | 없음 | 약 1.8 | 좌우교대·계단 | 약 20% |
| NORMAL | 8분음표 | 7개 | 가끔 2 | 약 3.0 | + 트릴 | 약 16% |
| HARD | 16분음표 | 7개 | 2~3 | 약 4.5 | + 연타(최대 3) | 약 11% |

간격을 초가 아니라 **몇 분음표**로 잡기 때문에 느린 곡과 빠른 곡의 체감이 비슷합니다.
박자가 한 옥타브 어긋나게 잡혀도 밀도가 흔들리지 않도록 박 길이를 77~200 BPM 범위로 접어 씁니다.

분석은 화면이 멈추지 않게 조금씩 나눠 돌립니다. 3~4분 곡에 보통 몇 초 걸립니다.

### 자동 채보의 한계

- 드럼이 또렷한 곡일수록 잘 맞습니다. 박자가 흐릿하거나 템포가 자주 바뀌는 곡은 어긋날 수 있습니다.
- BPM 이 절반이나 두 배로 잡히면 노트가 성기거나 빽빽해집니다. 난이도를 바꿔 조절하세요.
- 저장한 `.json` 은 사람이 읽을 수 있는 형식이라 직접 고쳐도 됩니다.
  `{ "t": 초, "lane": 0~6, "hold": 길이(초, 없으면 0) }` 목록입니다.

## 연주 화면

- **노트**는 위가 밝고 아래가 어두운 입체 타일입니다. 바깥 레인은 흰색, 안쪽은 파랑,
  가운데(`Space`)는 금색이라 색과 위치 둘 다로 구분됩니다.
- **긴 노트**는 양쪽에 레일이 있고 가운데가 밝은 기둥으로 그려집니다.
  잡고 있는 동안 기둥이 밝아지고 줄무늬가 빨라지며, 판정선에서 빛이 맥동합니다.
  손을 놓치면 기둥이 어둡게 죽습니다.
- **판정선** 아래에는 레인마다 **판정대**가 있어 누를 때 불이 들어옵니다.
- 치면 그 자리에서 **파문과 불꽃**이 퍼지고, 50콤보마다 판 전체가 한 번 번쩍입니다.
- **마디선**이 곡의 BPM 에 맞춰 흘러내려 박자를 눈으로 짚을 수 있습니다.
- PERFECT 가 아닐 때는 **빠름/느림**을 글자로 알려 줍니다.

연출은 미리 그려 둔 그림 조각(스킨 스크립트)을 얹는 방식이라 느린 기기에서도 부담이 적습니다.
`prefers-reduced-motion` 을 켜 둔 환경에서는 불꽃과 줄무늬 흐름을 끕니다.

## 가사 자막

곡 선택 화면의 **추가 설정 · 조작법** 안 **[가사 자막]** 버튼으로 자막을 직접 만들 수 있습니다.
음성 인식은 쓰지 않습니다 — 가사를 손으로 적고, 노래를 들으며 각 줄이 시작하는 순간에
버튼(또는 `Space`)을 눌러 시간을 맞추는 방식입니다(싱크 보정의 탭 방식과 같습니다).

1. 한 줄에 한 소절씩 적습니다.
2. **[노래 들으며 싱크 맞추기]** 를 누르면 곡이 처음부터 재생되며, 화면에 나온 줄이
   시작할 때마다 큰 버튼을 두드립니다. 마지막 줄까지 두드리면 자동으로 멈춥니다.
3. **[저장]** 을 누르면 이 곡에 자막이 등록됩니다(브라우저 `localStorage`, 채보 저장과 같은 방식).
4. 연주 중 자막이 거슬리면 같은 화면의 **[연주 중 자막 보기]** 로 껐다 켤 수 있습니다.

자막은 연주 화면 위쪽 판 시작 지점 부근에 한 줄씩 나타나며, 마지막 줄은 5초 동안 보인 뒤
사라집니다. **[가사 파일로 저장]** 으로 `.lyrics.json` 을 내려받아 따로 보관할 수 있습니다
(현재는 `songs/songs.json` 목록에서 자동으로 불러오지는 않고, 기기의 저장소에만 남습니다).

## 파일 구성

유지보수 편의를 위해 화면·모양·로직을 **`index.html` 한 파일**로 합쳐 두었습니다.
파일 하나만 복사하면 게임 전체가 그대로 옮겨집니다. 내부는 원래 나뉘어 있던
경계를 그대로 살려서, 주석으로 구획을 나눠 놓았습니다.

```
rhythm-game/
  index.html         화면 구조 + 모양(<style>) + 로직(<script> 5블록) 전부
    <style>            모양(옛 css/style.css)
    <script> fft.js     주파수 분석(FFT)
    <script> chart.js   채보 자동 생성
    <script> skin.js    노트·롱노트·판정대 그림 조각(미리 그려 캐시)
    <script> audio.js   재생·정확한 시계·효과음·내장 연습곡
    <script> game.js    판정·점수·그리기·화면 전환
  songs/             음악 파일과 목록(songs.json)
  tools/             점검용 스크립트(index.html 안의 스크립트를 그대로 뽑아 돌린다)
```

각 `<script>` 블록은 `/* ===== chart.js — 채보 자동 생성 ===== */` 같은 제목 주석으로
시작합니다. 편집기에서 그 제목으로 검색하면 옛 파일 하나를 열던 것과 똑같이 찾아갈 수
있습니다. 블록 순서는 의존 관계 순서(FFT → 채보 생성 → 스킨 → 오디오 → 게임 본체)를
그대로 유지합니다.

설정(노트 속도, 난이도, 싱크 보정값, 가운데 자동)과 곡별 최고 기록, 한 번 만든 채보는
브라우저의 `localStorage` 에 저장됩니다. 저장소를 못 쓰는 환경에서도 게임은 그대로 돌아갑니다.
